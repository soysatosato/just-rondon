# 「着いてからの歩き方」(AttractionVisitStep) の入れ方

`/sightseeing/[slug]` の詳細ページに出る「着いてからの歩き方」を投入する
スクリプト群の運用メモ。

## ファイルの分かれ方

| ファイル | 対象 | 件数 |
| --- | --- | --- |
| `seed-visit-flow.ts` | recommendLevel 5 | 11 / 11 |
| `seed-visit-flow-level4.ts` | recommendLevel 4 | 26 / 27 |
| `seed-visit-flow-level3.ts` | recommendLevel 3 | 54 / 63 |
| `seed-visit-flow-level2.ts` | recommendLevel 2・1 | 32 / 34 |
| `seed-visit-flow-new-spots.ts` | 2026-08 追加の11件 | 11 / 11 |

**全145ページ中134ページに投入済み（668ステップ）。**
残る11件はすべて下の「歩き方を書かないもの」に該当するため意図的に空。

`seed-visit-flow-new-spots.ts` だけ recommendLevel ではなく追加時期で
切っている。level 3・4 のファイルは既に対象を書き切っており、
あとから足したスポットを混ぜると「何件中何件やったか」が追えなくなるため。

投入ロジックは3ファイルとも同一。分けているのは出典コメントが1ファイルに
収まらなくなったためだけなので、ロジックを直すときは全部を直すこと。

どれも **ドライラン既定**。`--apply` を付けたときだけ書き込む。
投入前に既存のステップを `deleteMany` してから作り直すので、
何度流しても同じ結果になる。

## 書き方の基準

- **「何があるか」ではなく「なぜそれを見るのか」を書く。**
  名前を並べるだけの箇条書きは `AttractionSection` 側にすでにある。
  歩き方はその補集合として、対象が特別な理由を書く。
- **行く前に知っていると動きが変わる事実を入れる。**
  階段の段数、行列が伸びる時刻、休みの曜日、撮影の可否。
- **断定できない運用は逃がす。**
  開催日・時刻・曜日が変わりうるものは「公式で確認」と書く。
- 1ステップは2〜4文。`kind` は `arrival` / `highlight` / `missable` / `tip`。
- **マークダウンは使えない。** `AttractionVisitFlow.tsx` は `body` を
  プレーンテキストとして描画する（`ReactMarkdown` を通していない）ので、
  `**強調**` やリンク記法を書くと記号がそのまま画面に出る。
  本文（`AttractionStory`）側はマークダウンが効くので、混同しないこと。
  `seed-visit-flow-new-spots.ts` には投入前に記法を検出して止める
  チェックを入れてある。新しいファイルを作るときは同じものを入れること。

## 必ず裏を取る

**書いてから公式サイトで確認する。これを省くと事実誤認が残る。**
実績として、level 5 の11件で4件、level 4 の27件で5件、自分の書いた
下書きに誤りが見つかっている。よくある間違い方:

- 有名な逸話が俗説だった（ロンドン橋の買い手がタワーブリッジと
  取り違えた話、など）
- 数字が別の時代のものだった（ハンプトン・コートの年間食肉消費は
  ヘンリー8世期ではなくエリザベス1世期の記録）
- 展示物が復元だった（サイエンス・ミュージアムの階差機関は
  19世紀の実機ではなく1991年製）
- 制度が変わっていた（ビッグ・ベンの内部ツアーは英国居住者限定ではない、
  衛兵交代式は曜日固定ではなくなった）

確認した出典は各ファイル冒頭のコメントに URL 付きで残す。
**裏が取れなかったものは書かない。** 面白い話でも落とす。

## 歩き方を入れると見どころ節が消える

`components/sightseeing/sections.ts` の `VISIT_FLOW_SECTION` により、
歩き方が1件でも入っているページでは「見どころ」「必見」「展示されている」
などの節が本文から伏せられる。両方あると同じ対象を2回説明することになり、
薄いページに見えるため。

つまり **歩き方を入れた瞬間、そのページの「何を見るか」は歩き方が
丸ごと引き受ける。** 投入前に元の見どころ節を読み、そこにあった要素を
落とさないこと。

## 歩き方を書かないもの

### 物理的な場所を持たない商品

観光パスや周遊券は「着いてから」が存在しないので対象外。
DB上は `address` が `"-"` になっている。

- ロンドンパス (`the-london-pass`)
- マーリン・ロンドン・アトラクション・パス (`merlin-london-attractions-pass`)
- ゴールデンパス・ロンドン (`golden-pass-london`)
- ロイヤル・ミュージアムズ・グリニッジ デイパス (`royal-museums-greenwich-day-pass`)
- クリスマス・ライト・ロンドン・バスツアー (`christmas-lights-london-bus-tour-2025`)

これらに必要なのは歩き方ではなく「どのパスが誰に向くか」の判断材料。
`scripts/update-pass-products.ts` で本文側に書く。

とくにロンドンパスは、**ロンドンの主要な博物館・美術館がもともと無料**
（大英博物館、ナショナル・ギャラリー、V&A、テート、自然史博物館、
サイエンス・ミュージアム）である点を必ず書くこと。これを省くと
「100以上の施設」という宣伝文句だけで読者に判断させることになる。

### 終了・閉鎖した催し

行けない場所に「着いてからの歩き方」を書いても意味がないので対象外。
代わりに `fix-stale-attraction-notes.ts` で本文の冒頭に終了・閉鎖を明示する。

- ジュラシック・ワールド：エクスペリエンス — 2026年1月4日で開催終了
- ピーター・ハリソン・プラネタリウム — 改修のため閉鎖中（再開見込み2028年春）
- ファントム・ピーク — カナダ・ウォーター会場は2026年2月28日で閉幕。
  ウェストフィールド・ストラトフォード・シティで2026年12月4日に再開予定
- ザ・ムーンウォーカーズ — ライトルームでの公演が2026年4月12日で終了

再開したら歩き方を追加すること。ファントム・ピークは2026年12月に再開予定なので、
そのタイミングで新会場（Old Town / Town Square / Lakeside の3区画）向けに書く。

### 年号付きの季節イベント

日程が古いまま歩き方だけ足すと読者が混乱するので、**年次情報の更新が先**。

| slug | 現在の掲載 | 更新スクリプト |
| --- | --- | --- |
| `hyde-park-winter-wonderland-2025` | 2026年版 | `update-winter-wonderland-2026.ts` |
| `chelsea-winter-village-2025` | 2026年版 | `update-seasonal-events-2026.ts` |
| `rhs-chelsea-flower-show-2026` | 2027年版 | `update-seasonal-events-2026.ts` |
| `christmas-lights-london-bus-tour-2025` | 2026年版 | `update-pass-products.ts` |

**slug は変えない**（変えると既存URLが404になり検索流入を失う）。
表示名と本文だけを毎年更新する。slug の年号と表示年がずれるのは想定どおり。

毎年の作業: 各スクリプトの冒頭コメントにある日程を公式サイトで確認して
差し替え、`--apply` で再実行する。いずれも二重適用を防ぐ `done` 判定が
入っているので、流し直しても壊れない。

## 事実が古くなったとき

本文（`AttractionSection`）に直書きされた事実が古くなった場合は
`scripts/fix-stale-attraction-notes.ts` に1件ずつ足して直す。
部分一致で置換するので、再実行しても二重に適用されない。
