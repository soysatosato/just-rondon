# /add-modern-britain — 「いまのイギリス」の記事をDBに追加する

just-rondon の `/modern-britain` セクション用に、**最新の英国ニュースを起点にした
論考**を1本作成し、本番DB(`Content`/`ContentSection` テーブル、
`category: "modern-britain"`)に直接登録する。git の commit/push は一切不要 —
DBに1行INSERTするだけで `/modern-britain` と `/modern-britain/[slug]` に
(ISR再検証後、最大1時間以内に)反映される。

## このセクションの立ち位置(最重要)

サイトの読み物は4本ある。役割が被ると存在理由が消えるので、**厳格に分ける**:

|                             | 扱うもの              | 問い                                       |
| --------------------------- | --------------------- | ------------------------------------------ |
| `/column`                   | **過去**              | 「これはなぜこうなったのか」(起源・由来)   |
| `/events`                   | **今週の予定**        | 「今週何があるか」(ストライキ・催し・運休) |
| **`/modern-britain`(ここ)** | **最新ニュース+論考** | 「この出来事は何を意味するのか」           |
| `/british-english`          | 言葉                  | 「この表現、どういう意味?」                |

`/events` との違いが最重要。**あちらは予定表、こちらは論考**。

- `/events` = 「9月3日にナショナル・ギャラリーが臨時休館」— 読者の行動予定に効く情報
- `/modern-britain` = 「なぜいま美術館の職員がストに踏み切ったのか。その背景に
  ある賃金制度と、10年分の予算削減が意味するもの」— 読者の理解に効く論考

**ニュースを紹介して終わりにするのは禁止**。ニュース紹介は記事の入口に過ぎず、
本体は「掘り下げ」と「意見」。そちらが薄いと `/events` の劣化版になる。

## Step 1 — 既存項目を確認する(重複防止)

```bash
node -e '
const { PrismaClient } = require("@prisma/client");
const prisma = new PrismaClient();
(async () => {
  const rows = await prisma.content.findMany({
    where: { category: "modern-britain" },
    select: { title: true, slug: true, tags: true, createdAt: true },
    orderBy: { createdAt: "desc" },
  });
  console.log(JSON.stringify(rows, null, 2));
  await prisma.$disconnect();
})();
'
```

同じ論点を短期間に繰り返さないよう、直近の記事は必ず確認する。
政治・経済ネタが続いたら、文化・科学・スポーツ寄りに振るなど変化をつける。

## Step 2 — 最新ニュースを調査し、候補3件から選ばせる(必須)

`$ARGUMENTS` にテーマの指定があれば、それに沿ったニュース1件を調査して
Step 3 に進んでよい(この場合はニュース選択の質問を飛ばす)。指定が
無ければ、**執筆時点の英国ニュースを必ずWeb検索で調査**し、掘り下げがいの
ある候補を**3件**用意する。

出展リンクとする報道機関(いずれも一次に近い信頼できる情報源):

- BBC News、The Guardian、The Times、Financial Times、The Economist
- Sky News、The Independent、The Telegraph、Time Out London
- 分野別: Health Service Journal(NHS)、The Grocer(小売)、
  Inside Housing(住宅)、Times Higher Education(大学)

**一次資料に当たること**。報道が引用している元データがあれば必ずそちらも見る:

- 政府統計: ONS(国家統計局)、gov.uk の各省庁発表
- 規制当局・公的機関: CMA、Ofgem、Ofcom、Bank of England、NHS England
- 議会: 法案の審議状況、Select Committee の報告書
- 研究機関: IFS(財政研究所)、Resolution Foundation、King's Fund

候補を選ぶ基準:

- **掘り下げると制度・歴史・文化・伝統・流行・スポーツ・芸能に接続するもの**を選ぶ。
- 数日〜二週間前のものでよい。速報である必要はない。
- **3件は分野の系統をずらす**(政治・経済ネタばかりにしない)。
  Step 1 で確認した直近の記事の傾向を踏まえ、続いていた分野があれば
  今回の候補からは外すか比重を下げる。

避けるもの:

- 「今週これがある」で終わる催し情報(→ `/events` の役割)

3件そろったら `AskUserQuestion` でユーザーに選ばせる。各選択肢の `label`
にはニュースの要点を一言で、`description` に「掘り下げるとどこに
接続しそうか」を書く。勝手に1件決めて書き始めてはいけない。

## Step 3 — 論考の切り口を選ばせる

ニュースが決まったら、選ばれたニュースの内容と出典を簡潔に提示したうえで、
第2部(深掘り＆個人的見解)で**どこに重心を置くか**の切り口を**3案**
挙げて `AskUserQuestion` で選ばせる。各案は「何を軸に掘り下げるか」を
具体的に書く。例:

- 制度・歴史から入る(過去にも同じ構図があった、制度設計の変遷)
- 経済的条件・数字から入る(予算・賃金・価格などのデータ視点)
- 日本との比較を絡める(「日本との比較(毎回はやらない)」の条件を満たす場合のみ選択肢に含める)
- 文化・世相への波及から入る(この出来事が日常や価値観にどう滲み出るか)

3案は切り口の系統をずらす(全部が数字ネタ、全部が歴史ネタ、にしない)。
ユーザーが選んだ方向性に沿って Step 4 以降を書く。

### 記事の骨格(2部構成)

出典・データを本文全体にばら撒くと読みにくくなるので、**「紹介」と
「論考」を明確に分離する**。前半で事実関係と出典をまとめて片付け、
後半は出典参照を最小限にして書き手の思考に集中させる。

**第1部 — ニュース紹介(セクション1本のみ)**

- そのニュースの**リンクと内容**を紹介する。「何が起きたか」を
  淡々と、しかし十分な情報量で伝える。参照元へのリンクはニュース記事の英字タイトルをそのままアンカーテキストとして使用する。
- **ユーザーに明示する出典リンクは各部1本だけ**にする。裏取りで複数の
  報道・一次資料に当たってよいが、本文にMarkdownリンクを張るのは
  最も信頼できる1本(基本は一次報道)に絞る
- 数字は「**2026年8月時点で**」のように**いつ時点かを本文に書く**
- 分量は400字程度。ここで事実を出し切り、第2部では基本的に出典参照を増やさない

**第2部 — 深掘り＆個人的見解(セクション1〜2本)**

第1部で出した事実を前提に、以下を**地続きの論考として**書く。
サブ見出しで区切ってよいが、律儀に「背景」「影響」「意見」と
機械的に3分割する必要はない。書き手の思考の流れを優先する。

- **なぜ起きたか** — 背景・原因。制度、経済的条件、直前の政策変更など
- **何を意味するか** — 英国社会への影響。歴史・文化・制度との関係。
  「この国では過去にも同じ構図があった」という接続ができると強い
- **書き手はどう見るか** — 意見・問題提起・評価。**ここを必ず入れる**。
  ただし**本文で「筆者」と自称しない**。論考に入る合図は「ここからは私見です」のように
  書き、「筆者はこう見る」「筆者が引っかかるのは」は使わない。基本は主語を立てない。
- 出典リンクは**原則追加しない**。第1部の1本で足りるように書く。
  第二部で新しい事実(比較対象の数字など)が必要な場合のみ1本足す。

### 書き手の視点と文体

- **データ視点**。情緒や道徳感情ではなく、まず数字と構造を置く。
- 文章には、**英国らしい皮肉、ブラックユーモア、機知に富む表現**を積極的に取り入れる。
- **通説・耳触りの良いきれいごとを疑う・嫌う視点**。
- 硬い抽象名詞の多用(「インセンティブ設計」「制度的帰結」など)を避ける。

**避けるべき書き方**:

- **一文に条件節・言い換え・結論を全部詰め込む**長文。
- 全段落が同じ温度で進む**平熱な文章**。少なくとも1箇所は
  読者が「え」と思う跳躍・発見を入れる

文体は「です・ます」調。`/column` ほど硬くなく、`/british-english` ほど
ふざけない中間。読者に語りかける調子でよい。

### 日本との比較(毎回はやらない)

日本の社会・制度に当てはめた比較・考察を入れる。ただし**毎回やると
鬱陶しいので、3〜4本に1本程度**にとどめる。Step 1 で直近の記事を確認し、
前回やったなら今回は入れない。

入れる場合は、表面的な「日本もこうすべき」ではなく、
**制度の設計思想の違い**として書く。日本側の事実も裏を取ること。

## Step 4 — 執筆する

Step 3 でユーザーが選んだ切り口に沿って、以下の構成で記事を組み立てる。

### タイトルは先頭30字で決まる

日本語の検索結果でタイトルとして読めるのは**全角30字ほど**で、それ以降は
切り捨てられる。時事の記事は、読者が打つ語が固有名詞(politician名・制度名・
法案名・企業名)にほぼ限られるため、ここを外すと拾える語がなくなる。

- **先頭30字のうちに、そのニュースの固有名詞を必ず1つ置く**。
  「英国政府が」「与党が」のような一般名詞では検索に引っかからない。
- 全体は**50字前後**まで。
- 書き終えたら `title.slice(0, 30)` を目で見て、固有名詞が入っているか確かめる。

同じ考え方の詳しい説明と実例は `.claude/skills/add-column/SKILL.md` にある。

- `title`: 日本語タイトル。何のニュースの話か分かるものにする
- `engTitle`(任意): 英語タイトル。**スラッグ生成に使われるので付けるのが望ましい**
  (無い場合は日本語タイトルから生成を試み、失敗すると日付スラッグになる)
- `summary`: 2〜3文。何が起きたかと、この記事が取る立場を先出しする
- `mainText`: **使わない**(空にする)。summary の直後にもう一段リード文が入ると
  同じ話を二度読まされるうえ、本編に入る前に結論を三回言うことになる。
  言いたいことは summary か第1部の本文に入れる
- `sections`: **2〜3個** (原則２個)。上記「記事の骨格(2部構成)」に対応させる
  (第1部の「ニュース紹介」1本 + 第2部の「深掘り＆個人的見解」1〜2本　原則（一本）)。
  各セクションは
  - `title`: 見出し。**元記事の英字タイトルを和訳したもの**を第1部の見出しに使う
    (報道が何と報じたかをそのまま見せる)。第2部は機械的に「背景」「意見」と
    付けず、論考の内容が伝わる見出しにする
  - `subtitle`: 一言(任意)
  - `description`: Markdown形式の本文。第1部は200〜400字程度、
    第2部は各セクション300〜600字程度。箇条書き・表・引用も使ってよい
  - `displayOrder`: 0始まりの連番。**書き忘れやすい**。登録前に全セクションに
    入っているか必ず確認する(無いとスクリプトがエラーで弾く)
- `image`: **必須**。Wikimedia Commons(`https://upload.wikimedia.org/...`)上の
  パブリックドメインまたは再利用可能ライセンスの画像URL。一覧カードと詳細ページの
  両方がこの値を見ており、**null だとどちらにも画像が出ない**(スクリプトは
  弾かないので気づきにくい)。
  - **必ずサムネイルURLを使う**。Commons の原寸ファイルは 10MB を超えることが
    あり、カードに貼ると読み込みが目に見えて重くなる。
    `.../commons/a/ac/Name.jpg` ではなく
    `.../commons/thumb/a/ac/Name.jpg/1280px-Name.jpg` の形にする
    (`thumb/` を挟み、末尾に `1280px-` + 元のファイル名を足す)。
  - 登録前に `curl -sIL "<URL>" | grep -Ei "^(HTTP/|content-length)"` で
    200 が返ることとサイズを確認する。Commons の検索結果に出たURLでも
    綴りを取り違えると 404 になる。
- `tags`: **必須**。1〜3個。正典は `lib/modern-britain-taxonomy.ts`。
  ここに無い値を入れると登録スクリプトがエラーで弾く。
  - `food` — 食と店
  - `money` — 物価・お金
  - `manners` — 習慣・マナー
  - `media` — テレビ・ネット
  - `society` — 世相・ニュース

## Step 5 — DBに登録する

組み立てたJSONをスクラッチパッド等の一時ファイルに書き出し、リポジトリの
ルートで以下を実行する。

```bash
npx tsx scripts/create-modern-britain.ts <一時ファイルのパス>
```

成功すると `Created modern-britain entry: /modern-britain/<slug> (id=...)`
が出力される。

エラーが出た場合の対処:

- スラッグ重複 → `engTitle` を微調整して再実行する。
- `Unknown tag "..."` → `tags` に正典外の値が入っている。Step 4 の一覧から選び直す。

## Step 6 — 完了報告

git の操作(commit, push, branch作成など)は一切行わない。
最後に、公開された記事のタイトルと `/modern-britain/<slug>` のURL、
および参照した主な出典をユーザーに報告する。
